## Implementation and qualification record

CK-08 now implements the internal typed query and evidence boundaries under
`src/codex_usage_tracker/agent_kernel/query/` and
`src/codex_usage_tracker/agent_kernel/evidence/`. The service compiles only
registered Foundation/Cutover requests, opens one query-only snapshot per
request, returns deterministic complete-result ordering, and resolves typed
selectors and provenance without a refresh or writer path. Pagination uses
versioned signed keyset cursors bound to the request, plan, publication, and
logical order. Exact counts remain opt-in.

The durable
[CK-08 qualification evidence](../../decisions/evidence/ck08/fact-backed-query-and-evidence-qualification.json)
records:

- 21 / 21 admitted plans and 42 / 42 fact-backed variants with 42 unique
  comparison digests;
- exact typed rows, grades, ordering, request digests, and ordered evidence
  references against the CK-07A authority;
- all 14 selector kinds and six provenance kinds, cursor tamper and binding
  denial, query-only write denial, and rebuild/replacement/late-event replay;
- SQL sources and exact `EXPLAIN` structures plus response-byte measurements;
- standard and production query-only synthetic database-v1 scale evidence.

The committed
[raw scale benchmark](../../decisions/evidence/ck08/query-scale-raw-benchmark.json)
is generated by `scripts/benchmark_ck08_query_scale.py` and binds the reviewed
production-source digest, exact database and schema digests, environment,
command, raw samples, and measurements digest. The qualification collector
fails closed when that artifact is absent, stale, or altered.

Three plans are fact-table-sufficient at the measured required gates:
`latest_publication_delta`, `data_health`, and `resource_hotspots`.
The remaining 18 plans are correctness-qualified but exceed at least one
standard SQL, service-latency, or response-byte gate and are recorded as
projection-required inputs for CK-09. CK-08 adds no projection and exposes no
public surface.

The separate full publication-path scale attempt is retained honestly: source
generation and ingestion completed, but CK-07 publication lifecycle preparation
exceeded the bounded run after more than 15 minutes. CK-08 did not modify that
predecessor path. The query-path measurements therefore identify their fixtures
as exact synthetic database-v1 fact databases, not publication-valid artifacts.

The exact wheel grew from the retained CK-07A main artifact's 320,867 bytes to
373,481 bytes after adding the nine production query/evidence modules. The
release-candidate ratchet is 383,000 bytes, 2.55% above the measured CK-08
artifact and below the policy's 25% maximum headroom. The source distribution
remains below its unchanged 820,000-byte ceiling.

Exactly one comprehensive final reviewer reported three findings. All three
were accepted and corrected: the registry now enforces the exact ordered
evidence role/kind sequence, allowance boundary pairs reject identical
observations, and scale qualification consumes the revision-bound executable
benchmark artifact. Bounded post-review validation passed 89 tests plus Ruff,
Mypy, scope, and diff checks. Reviewer token attribution remains pending
because the installed 0.28 CLI does not support the strict aggregate command;
the bounded measurement was not retried.

## Historical blocking prerequisite reproduction

The following reproduction is retained as historical evidence. It is not the
current CK-08 blocker. CK-07A corrected the scenario-to-publication seam and
requalified all 80 fact-backed variants; its canonical evidence is
[`fact-backed-oracle-and-seam-qualification-evidence.json`](../../decisions/evidence/ck07a/fact-backed-oracle-and-seam-qualification-evidence.json).
The retained evidence below explains why CK-08 previously stopped and why
answer-backed runtime tables remain forbidden.

CK-08 cannot implement or accept the named plans against the unchanged CK-03
question oracles without violating the fact-backed runtime boundary. The
checked-in `Q-ACC-01` boundaries case asks for one exact half-open window and
expects 18 calls and 6,250 uncached-input tokens. Publishing the same synthetic
fixture through the CK-06 adapter and CK-07 writer produces 2 canonical calls
and 1,873 uncached-input tokens in that window.

The CK-04 Candidate A proof does not resolve this mismatch. Its query reads a
candidate-only `question_cases` table populated from `oracle_case` grading
records. The database-v1 contract explicitly forbids that table in the
production package. Adding an equivalent table, reading `oracle_case` records
at runtime, or changing a query to return the frozen expected row would make
the grading truth the answer source instead of deriving the answer from
canonical facts.

The exact inputs, hashes, SQL result, and contract references are recorded in
[`fact-backed-oracle-prerequisite-gap.json`](../../decisions/evidence/ck08/fact-backed-oracle-prerequisite-gap.json).
Corrective packet
[CK-07A](ck-07a-reconcile-fact-backed-oracles-and-qualify-seams.md) owns this
prerequisite. Before CK-08 can resume, the authority set must freeze Foundation/Cutover
question cases whose expected rows are independently calculated from the
canonical facts emitted for the same typed requests. The replacement must keep
all 21 named plans, 42 variants, grades, formulas, selectors, and limits, and
must prove the oracle without a candidate-only answer table. At the time of
this reproduction this packet remained unchecked and no registry entry,
query/evidence implementation, projection, public API, or CK-09 work was
admitted. CK-07A has since satisfied the prerequisite. CK-08 may now implement
only the internal fact-backed query/evidence scope above; the historical record
still admits no projection, public API, or CK-09 work.
